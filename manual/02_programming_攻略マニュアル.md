## 第1章 問3の解き方（最初に読む）

### 1-1. 問3はどういう問題か

問3は、**ある処理（探索、経路計算、パズルなど）のアルゴリズムを説明文で示し、それを擬似言語で書いたプログラム**を読ませる問題。毎回のテーマは違うが、設問はほぼ次の4種類。

1. **プログラムの空欄を埋める**（条件式・代入式・関数呼出し）
2. **具体的なデータで動きを追う（トレース）**（配列の中身、戻り値、実行回数）
3. **計算量・実行回数を答える**
4. **改良したときの変化を答える**（どこを直すか、何が速くなるか）

アルゴリズムの説明は**全て問題文に書いてある**。知らないアルゴリズムが出ても、説明を読めば解けるように作られている（例：2018秋のウェーブレット木、2023春のカラツバ法）。

### 1-2. 解く手順

1. **問題文の冒頭で前提を確認**（1分）：配列の要素番号は0から始まるか1から始まるか、÷は切捨てか、大域変数は何か。
2. **アルゴリズムの説明を図・例と一緒に読む**：説明文の具体例（図の配列、表の値）は、あとで空欄の答えを検算する材料になる。
3. **変数の意味を表にまとめる**：問題文にある変数・配列の説明（「topは…を表す」）を、プログラムの横にメモする。
4. **空欄を埋める**：説明文の手順とプログラムの行を1対1で対応させる。
5. **埋めた式を、図の具体例で1回動かして確かめる**（ここを省くと失点する）。
6. **トレースの問題は表を書いて追う**（下の1-3）。

### 1-3. トレースの書き方

変数ごとに列を作り、1行実行するたびに値を書き足していく。頭の中だけで追うと必ず間違える。

例：配列 a ＝ {5, 3, 8} の最大値を求めるプログラム

```
max ← a[1]
for (i を 2 から 3 まで 1 ずつ増やす)
  if (a[i] > max)
    max ← a[i]
  endif
endfor
```

| 実行した行 | i | a[i] | a[i] > max | max |
|---|---|---|---|---|
| max ← a[1] | — | — | — | 5 |
| for（1回目） | 2 | 3 | 偽 | 5 |
| for（2回目） | 3 | 8 | 真 | **8** |

### 1-4. 採点講評が毎年言っていること

| 失点の原因 | 講評での言われ方（例） | 防ぎ方 |
|---|---|---|
| **境界値の誤り** | 「topがlastより小さい」と書き、等しい場合を含まない（2021秋）／for文の条件の誤り（2018春） | 最小値・最大値を代入して確かめる |
| **不等号の向き** | 最小値を求める比較の大小が逆（2024春） | 「より小さければ更新」を言葉にしてから書く |
| **添字の取り違え** | 二次元配列の要素番号の誤り（2025秋） | 表に i, j を書き込んで、参照するマスを矢印で確認 |
| **式の一部しか書かない** | 誤差を元の値に足し込む部分がない（2020）／更新起点ノードの距離だけ（2024春） | 「何に」「何を」加えるかを両方書く |
| **書き方の不正確さ** | 代入文になっていない、変数名の誤り、括弧の閉じ忘れ（2016） | 問題文の変数名を正確に写す |
| **回数の数え間違い** | 実行回数の把握（2020、2021秋） | 1回の処理で各要素が何回扱われるかで数える |

## 第2章 必ず知っておく基礎知識

### 2-1. 擬似言語の読み方

2024年度春期から、問題冊子の最初に「擬似言語の記述形式（基本情報技術者試験，応用情報技術者試験用）」が載るようになった。基本情報技術者試験の科目Bと同じ書き方。

| 記述 | 意味 |
|---|---|
| `○整数型: f(整数型: n)` | 整数を返す関数fの宣言（引数nは整数） |
| `○proc(整数型: x)` | 戻り値のない手続の宣言 |
| `整数型: x ← 0` | 変数の宣言と初期値の代入 |
| `x ← x + 1` | 代入（右辺を計算して左辺に入れる） |
| `if (条件) … elseif (条件) … else … endif` | 上の条件から順に調べ、最初に真になったものだけ実行 |
| `while (条件) … endwhile` | **条件が真の間**繰り返す（最初に偽なら1回も実行しない） |
| `do … while (条件)` | 1回実行してから、条件が真の間繰り返す |
| `for (i を 1 から n まで 1 ずつ増やす) … endfor` | i＝1, 2, …, n で繰り返す（**両端を含む**） |
| `return x` | 値を返して関数を終える（繰返しの途中でも終わる） |
| `and`, `or`, `not` | かつ、又は、否定 |
| `mod`, `÷` | 剰余、商（問題文で切捨てと定義されることが多い） |
| `≠`, `≦`, `≧` | 等しくない、以下、以上 |
| 大域変数 | 全ての関数から使える変数（問題文に「大域」と書かれる） |

- **配列の要素番号**：特に断りがなければ**1から**。0から始まる問題もあり、その場合は冒頭に明記される。
- **while の条件は「続ける条件」**。「〜になったら終わる」と説明されていたら、その否定を書く。

### 2-2. 配列と添字の計算

**一言で**：2次元の盤面や木を1次元の配列で表す問題が頻出。「何行何列目が何番目か」を式で書けることが必要。

| 変換 | 0から始まる場合 | 1から始まる場合 |
|---|---|---|
| (行r, 列c) → 番号（列数W） | r × W ＋ c | (r − 1) × W ＋ c |
| 番号 → 行 | 番号 ÷ W | (番号 − 1) ÷ W ＋ 1 |
| 番号 → 列 | 番号 mod W | (番号 − 1) mod W ＋ 1 |

- **上下左右への移動**：移動量を配列に入れておく（例：dr＝{−1, 1, 0, 0}，dc＝{0, 0, −1, 1}）。移動先が盤面の内側か（1 ≦ r ≦ H かつ 1 ≦ c ≦ W）を必ず確認する（2025春、2018春）。
- **3×3のブロックの先頭**（数独型）：(x ÷ 3) × 3（0から始まる場合。2022春）。
- **配列で表す木**：1から始まる場合、親 i の子は 2i と 2i＋1、子 i の親は i ÷ 2。0から始まる場合は子が 2i＋1 と 2i＋2、親が (i − 1) ÷ 2。

### 2-3. 計算量（O記法）

**一言で**：データの件数 n が増えたとき、処理時間がどう増えるかの目安。定数倍や小さい項は無視する。

| 計算量 | 意味 | 例 |
|---|---|---|
| O(1) | 件数に関係なく一定 | 配列の添字で直接取り出す、ハッシュ表の探索（衝突なし） |
| O(log n) | 半分ずつ減らす | 2分探索、ヒープへの追加・取出し、平衡木の探索 |
| O(n) | 全件を1回ずつ見る | 線形探索、最大値を求める |
| O(n log n) | 効率のよい整列 | マージソート、ヒープソート、クイックソート（平均） |
| O(n²) | 二重ループ | バブルソート、選択ソート、挿入ソート |
| O(nm) | 表の全マスを埋める | 動的計画法（表が n 行 m 列） |

**よく問われる「最悪の場合」**

| アルゴリズム | 平均 | 最悪 | 最悪になる入力 |
|---|---|---|---|
| 2分探索木の探索 | O(log n) | O(n) | 整列済みのデータを順に追加（木が一直線になる） |
| ハッシュ表の探索 | O(1) | O(n) | 全てのキーが同じハッシュ値になる |
| クイックソート | O(n log n) | O(n²) | 基準値が毎回最大か最小になる |

**実行回数の数え方**：二重ループ「for i を 1 から n、for j を 1 から m」なら内側は n × m 回。「for j を i から n」なら n＋(n−1)＋…＋1 ＝ n(n＋1)/2 回。

### 2-4. スタックとキュー

| | スタック | キュー |
|---|---|---|
| 一言で | 後に入れたものを先に出す（**LIFO**） | 先に入れたものを先に出す（**FIFO**） |
| 操作 | push（積む）、pop（取り出す） | enqueue（並ぶ）、dequeue（取り出す） |
| 使い道 | 深さ優先探索、関数呼出し、括弧の対応、逆ポーランド記法の計算 | 幅優先探索、到着順の処理、バッファ |
| 配列での実装 | top（一番上の位置）を増減 | head（先頭）と tail（末尾）。**リングバッファ**では位置を mod で折り返す |

2017春：探索に使うデータ構造をキューからスタックに変えると、探索の順序が幅優先から深さ優先に変わる（スタック側の正答率が低かった）。

### 2-5. 連結リスト

**一言で**：各要素が「値」と「次の要素への参照（ポインタ）」を持ち、参照をたどってつながっている構造。

- **挿入**：新しい要素の next に「挿入位置の次」を入れ、前の要素の next を新しい要素にする（**この順番を逆にするとつながりが切れる**）。
- **削除**：前の要素の next を、削除する要素の next に付け替える。
- 配列との比較：途中への挿入・削除は速い（要素の移動が不要）が、k番目の要素を取り出すには先頭からたどる必要がある。

### 2-6. 木（2分探索木・ヒープ・平衡木）

**2分探索木**
- 一言で：どの節でも「**左の子孫 ＜ 節 ＜ 右の子孫**」となる2分木。探索は根から大小を比べて左右に進む。
- 削除：子がない→そのまま消す／子が1つ→その子で置き換える／子が2つ→左部分木の最大（又は右部分木の最小）で置き換える。
- 弱点：追加の順序によって偏ると、探索が O(n) になる。

**平衡2分探索木（AVL木）**（2023秋）
- 全ての節で左右の部分木の高さの差を1以下に保つ。崩れたら**回転**で直す。探索・追加・削除が O(log n)。

**ヒープ**
- 一言で：「**親 ≦ 子**」（最小ヒープ）を満たす完全2分木。根が最小値。配列で表す（2-2の親子の式）。
- 追加：末尾に置き、親より小さい間、親と交換（上方移動）。
- 最小値の取出し：根を取り出し、末尾を根に移し、子のうち小さい方より大きい間、その子と交換（下方移動）。
- 追加・取出しとも O(log n)。**優先度付きキュー**の実装に使う（ダイクストラ法の高速化など）。
- 注意：ヒープは**安定でない**（同じ値の順序が保たれない）。同じ値を受付順に出したいなら、比較に受付番号を加える。

**木の巡回**：先行順（節→左→右）、中間順（左→節→右。2分探索木では小さい順になる）、後行順（左→右→節）。

### 2-7. ハッシュ表

**一言で**：キーからハッシュ関数で格納位置を計算し、O(1) で探せるようにする表。

- **衝突（シノニム）**：違うキーが同じ位置になること（2009春で問われた）。
- **チェイン法**：同じ位置の要素を連結リストでつなぐ。
- **オープンアドレス法**：空いている別の位置を探す（線形探索法なら次の位置へ）。**削除した位置には「削除済み」の印を付ける**（空にすると、その先に置かれた要素が探せなくなる）。
- **負荷率**（格納数 ÷ 表の大きさ）が高いほど衝突が増え遅くなる。

### 2-8. グラフと探索

**一言で**：点（ノード）と辺でつながりを表す。道路網、ネットワーク、依存関係など。

- **表し方**：隣接行列（n×nの表）／隣接リスト（点ごとにつながる点の一覧。2021秋は配列 edgefirst・edgenext で表現）。

**幅優先探索（BFS）**：始点に近い順に調べる。**キュー**を使う。最初に見つけた解が**最小手数**。

```
始点をキューに入れ，訪問済みにする
while (キューが空でない)
  キューから取り出した点を u とする
  u に隣接する全ての点 v について
    v が未訪問なら，v を訪問済みにしてキューに入れる
```

- 終了条件は「**キューが空になったら**」（2025春で正答率がやや低かった）。
- **訪問済みにするのはキューに入れるとき**（取り出すときにすると同じ点が何度も入る）。

**深さ優先探索（DFS）**：行けるところまで進み、行き止まりなら戻る。**スタック**か**再帰**で書く。全ての解を探す問題（迷路、パズル）向き。

**ダイクストラ法**（2024春）：辺の重みが0以上のとき、始点から各点への最短距離を求める。
1. 始点の距離を0、他を∞にする。
2. 未確定の点のうち**距離が最小**の点 u を確定する。
3. u に隣接する点 v について、**d[u] ＋ (u から v への辺の重み)** が d[v] より小さければ d[v] を更新する。
4. 全ての点が確定するまで 2〜3 を繰り返す。

計算量は配列で最小を探すと O(V²)、ヒープを使うと O((V＋E) log V)。

### 2-9. 再帰とバックトラック

**一言で**：関数が自分自身を呼び出すこと。大きな問題を「同じ形の小さい問題」に分けて解く。

- 必ず**終了条件（基底ケース）**を書く。ないと無限に呼び出す。
- 例：階乗 f(n) ＝ n × f(n − 1)、f(0) ＝ 1。
- **呼出しの流れの追い方**：呼び出すたびに「呼出し元に戻ったら次に何をするか」をメモしておく（2022秋：(5,5) に着いた後、呼出し元の (5,4) に戻り、次の方向を試す）。

**バックトラック**（深さ優先で全ての候補を試す）
```
○try(状態)
  if (完成している) 解を記録して return
  for (次の候補それぞれについて)
    if (置ける)
      置く            // 状態を進める
      try(次の状態)
      取り除く        // 状態を元に戻す（★忘れると他の候補が壊れる）
```
2022春：「処理B」で盤面とデータ構造を、置く前の状態に戻す必要があった（正答率が低かった）。

### 2-10. 動的計画法

**一言で**：大きな問題を小さな部分問題に分け、**部分問題の答えを表に記録して使い回す**ことで、同じ計算の繰返しをなくす方法。

**手順**
1. **部分問題を決める**：「先頭からi文字とj文字の答え」「重さの上限wまでの最大価値」など。
2. **漸化式を立てる**：大きい部分問題の答えを、小さい部分問題の答えで表す。
3. **初期値を決める**：0行目・0列目など。
4. **小さい方から表を埋める**。

**代表例**

| 問題 | 表 | 漸化式 |
|---|---|---|
| ナップサック（2017秋） | dp[i][w]：品物1〜iで重さw以下の最大価値 | dp[i][w] ＝ max(dp[i−1][w], dp[i−1][w−重さi] ＋ 価値i) |
| 最長共通部分列LCS（2025秋） | L[i][j]：先頭i文字とj文字のLCSの長さ | 文字が等しければ L[i−1][j−1]＋1、違えば max(L[i−1][j], L[i][j−1]) |
| 編集距離 | D[i][j]：先頭i文字をj文字に変える最小操作数 | min(D[i−1][j]＋1, D[i][j−1]＋1, D[i−1][j−1]＋(違えば1)) |

- 計算量は**表の大きさ**（n × m）。
- 改良の定番：表全体ではなく**直前の行だけ**を持てば、領域を O(m) に減らせる。

**どこを見ればよいか**：表のマス (i, j) を計算するとき、**左（j−1）・上（i−1）・左上（i−1, j−1）**のどれを使うかを図で確認する。2025秋は二次元配列の要素番号の誤りが多かった。

### 2-11. 整列（ソート）

| 方法 | 考え方 | 計算量 | 安定 |
|---|---|---|---|
| バブルソート | 隣同士を比べて交換 | O(n²) | ○ |
| 選択ソート | 残りの最小値を選んで先頭と交換 | O(n²) | × |
| 挿入ソート | 整列済みの部分の適切な位置に挿入 | O(n²)（ほぼ整列済みなら O(n)） | ○ |
| マージソート | 半分に分けて整列し、併合 | O(n log n) | ○ |
| クイックソート | 基準値より小さいものと大きいものに分ける | 平均 O(n log n)、最悪 O(n²) | × |
| ヒープソート | ヒープから最小値を順に取り出す | O(n log n) | × |

**安定**：同じキーの要素の元の順序が保たれること。

### 2-12. 数の計算

- **剰余（mod）と商（÷）**：桁の取り出し（n mod 10 で1の位、n ÷ 10 で残り）、周期的な位置（リングバッファ）、偶数・奇数の判定。
- **エラトステネスの篩**（2024秋）：2から順に、素数の倍数を消していく。**√n まで**調べれば十分。倍数を消すのは **i × i から**でよい（それより小さい倍数は既に消えている）。
- **多倍長整数**（2023春）：大きな数を配列の各要素に桁ごとに入れて計算する。**カラツバ法**は、掛け算の回数を4回から3回に減らす分割統治。
- **ユークリッドの互除法**：最大公約数 gcd(a, b) ＝ gcd(b, a mod b)、b＝0 なら a。

### 2-13. 機械学習系のアルゴリズム

- **k-means法**（2021春）：k個の重心を決め、各点を最も近い重心のクラスタに入れ、重心を計算し直す。重心が変わらなくなるまで繰り返す。
- **パーセプトロン**（2019秋）：入力に重みを掛けて合計し、しきい値を超えたら1を出力する。単純パーセプトロンは**直線で分けられる問題しか解けない**（排他的論理和などは解けない）。
- シラバスの用語例には、機械学習・ディープラーニング・大規模言語モデル（LLM）・Transformer も含まれる。科目Bでは「仕組みを説明文で与えてプログラムにする」形で出題される。

## 第3章 よく出る問題の型（6パターン）

### 型1：探索（2025春、2022秋、2022春、2021秋、2018春、2017春）
盤面や迷路を配列で表し、幅優先・深さ優先・再帰で解を探す。
- 問われること：移動先の計算と範囲チェック、訪問済みの管理、終了条件、状態の復元、探索の順序。

### 型2：最短経路・グラフ（2024春、2021秋）
ダイクストラ法、一筆書き。
- 問われること：最小値を選ぶ条件（不等号）、距離の更新式、ループの回数（辺の数の2倍など）。

### 型3：動的計画法（2025秋、2017秋）
- 問われること：漸化式の空欄、表の一部を埋める、計算量、領域の削減。

### 型4：木構造（2023秋、2018秋、2015秋）
2分探索木、AVL木、ウェーブレット木。
- 問われること：再帰による追加・探索、回転、高さ、平衡が崩れる入力、計算量。

### 型5：数値・データ処理（2024秋、2023春、2020）
素数、多倍長、画像処理。
- 問われること：配列の添字、ループの範囲（√n まで、i×i から）、実行回数の比較。

### 型6：AI・機械学習（2021春、2019秋）
- 問われること：説明された計算手順をそのままプログラムにする、収束するまでの繰返し、確率の計算。

## 第4章 空欄・記述の書き方（良い答え・悪い答え）

### 4-1. 条件式の空欄

**例1**：幅優先探索の while の条件

| | 答え | 評価 |
|---|---|---|
| ✕ | キューが空 | 「続ける条件」と「終わる条件」が逆 |
| ○ | キューが空でない（問題文の関数名で書く：`not isEmpty(q)` など） | |

**例2**：配列の末尾を超えないかの確認（右の子がある場合だけ比べる）

| | 答え | 評価 |
|---|---|---|
| ✕ | `heap[c + 1] < heap[c]` | 右の子がないときに配列の外を参照する |
| ✕ | `c + 1 < size and heap[c + 1] < heap[c]` | 右の子がちょうど最後の要素のときを見落とす |
| ○ | `c + 1 ≦ size and heap[c + 1] < heap[c]` | 境界を含めて正しい |

### 4-2. 代入式の空欄

**例**：誤差を周りの画素に足し込む（2020）

| | 答え | 評価 |
|---|---|---|
| ✕ | `d × ratio[c] ÷ denominator` | 足し込む値だけで、どこに足すかがない |
| ○ | `pixel[y][x] + d × ratio[c] ÷ denominator` | 元の値に加える式になっている |

### 4-3. 記述（理由・特徴）

| 問われ方 | 型 |
|---|---|
| 改良の効果 | 「〜を記録して再利用するので，〜の計算が不要になり，O(…)からO(…)になる」 |
| 最悪になる入力 | 「全てのキーのハッシュ値が同じになる場合」「整列済みのデータを順に追加した場合」 |
| データ構造を変える理由 | 「途中への挿入・削除で要素の移動が不要になるから」 |
| 順序が重要な理由 | 「降順に整列しておくと，〜が早く見つかり探索を打ち切れるから」（並べる向きまで書く。2017春） |
